# `WUI.*` JS API Index

[← Index](README.md) · See also [source-layout.md](source-layout.md) for where each file lives.

| Symbol | File | Notes |
|---|---|---|
| `WUI.responsive.observe(el, onResize, opts)` | `build/src/core/responsive.js` | ResizeObserver primitive. `-> {disconnect()}`. `onResize` gets `{tooSmall, width, height}`. `opts.minWidth`/`minHeight` gate `tooSmall`. Falls back to a throttled `window.resize` + `getBoundingClientRect()` when `ResizeObserver` is unavailable. |
| `WUI.chart(el, opts)` (uPlot) | `JS/wui-charts.js` | **Gotcha:** `opts.series` lists **only the real data series** — no leading `{}` x-axis placeholder (that's internal to `_buildConfig`). `opts.data[0]` must be real ascending Unix-**second** timestamps, not small sequential integers, or uPlot's time-scale silently renders nothing visible. DPR handled internally by uPlot, no extra code needed. Auto-resizes via `WUI.responsive.observe`. `opts.neon` (2026-07-27, see below) adds an opt-in glow. |
| `WUI.pie(el, opts)` / `WUI.donut(el, opts)` | `JS/wui-charts.js` | Raw Canvas 2D. Auto-resizes + devicePixelRatio-correct (`_fitCanvasToBox` helper). `data` is an array of `{label, value, color}` slice objects, not columnar. `opts.center = {label, sub}` overlays text in the donut hole (use this instead of hand-rolling a center overlay). **Gotcha:** `opts.legend: true`'s auto-generated legend always appends as the host element's **last child**, right after the canvas — there's no separate-container option in the API. To dock it into a `.wui-tile-legend` slot (see [css-classes.md](css-classes.md)) instead of leaving it inline: grab `host.lastElementChild` once, right after chart creation, and `appendChild` it into the dock. Safe across redraws/theme changes — `_renderPieLegend` only resets that same element's `innerHTML`, it never re-appends. `opts.neon` (2026-07-27, see below) adds an opt-in glow. |
| `WUI.gauge(el, opts)` | `JS/wui-charts.js` | `opts.value` (0-100), `opts.zones` (threshold color bands, default `<40 danger, <70 warning, else success`), `opts.status` (pre-localized status string — the engine never calls `WUI.i18n` itself), `opts.height` (fixed; container height doesn't drive it, only width auto-resizes). Auto-resizes + DPR-correct. `opts.neon` (2026-07-27, see below) adds an opt-in glow. |
| `WUI.barRow(el, opts)` | `JS/wui-charts.js` | Pure CSS/DOM (`.wui-bar-row`, percentage `linear-gradient` fill) — **no canvas, no resize wiring needed**. Already reflows for free via CSS; has its own `@container wui-tile (max-width:220px)` density-reduction rule in `weoc-progress.css`. `rows: [{label, value, segments: [{pct, color}]}]`. `opts.neon` (2026-07-27, see below) adds an opt-in glow. |
| `opts.neon` — `WUI.chart`/`pie`/`donut`/`gauge`/`barRow` | `JS/wui-charts.js` + `CSS/weoc-ui/weoc-charts.css` (new file, 2026-07-27) | Opt-in glow, added to all 5 chart-family factories the same session. Values: `false`/omitted (default, zero visual change), `true` (→ `'primary'` severity), or `'primary'\|'secondary'\|'success'\|'warning'\|'danger'\|'info'` — same 6 severities and `--color-{name}-glow` tokens as `.wui-btn.neon-outline`/`.wui-fab.neon-outline` (`weoc-interactive.css`). Two different mechanisms depending on how each one draws: **canvas-drawn** (`pie`/`donut`/`gauge`) sets `ctx.shadowBlur`/`ctx.shadowColor` around the relevant `stroke()`/`fill()` calls and resets to 0 right after (same technique `kpi-sparklines.js`'s hand-rolled sparkline glow already used — see the KPI-recipe docs card in `kpi-recipes.html` section 2). **DOM/CSS-drawn** (`chart` = uPlot canvas host; `barRow` = `.wui-bar-row .fill` spans) toggles a `wui-chart-neon-{severity}` / `wui-barrow-neon-{severity}` class on the host container, matched by a `filter: drop-shadow(...)` rule in the new `weoc-charts.css` (imported by `weoc-ui-core.css`, module #21). Class survives `update()`/theme-toggle redraws, cleared on `destroy()`. Same-session sibling work: `.wui-badge.neon`/`.wui-chip.neon` (`weoc-labels.css`), `.wui-plane.neon` (`weoc-containers.css`), `.wui-progress-ring.neon`/`.wui-progress-bar.neon` (`weoc-progress.css`, `filter:drop-shadow` not `box-shadow` — SVG stroke/rounded-fill shapes don't sit right under a box-shadow) — all documented as rows in [css-classes.md](css-classes.md), all following this exact same convention. |
| `WeocMap.create(rootOrSelector, opts)` / `.autoInit()` | `JS/weoc-map.js` | **Flat global** (`window.WeocMap`), not nested under `WUI`. Reference implementation to copy for new board maps. Auto-resizes via `WUI.responsive.observe` on `this._viewDiv`; `.resize()` stays safe to call redundantly/manually on top of that. |
| `WUI.i18n.register/t/tFor/getLang/setLang/toggleLang/apply/mark/mountTopToggle` | `build/src/core/i18n.js` | Cross-frame/tab sync via the native `storage` event. Fires `wui:langchange` with `{lang, rtl}` detail on every `setLang`/`toggleLang`. Legacy shims kept working: `<resource id>`/`[l-key]`, `[isresources="yes"][resourcekeys]`, `.resourceTip[data-resource]`, `.tooltip-localization[titleEN][titleAR]`, `window.getResource`/`changeLang`. |
| `WUI.setTheme(theme, opts)` / `WUI.toggleTheme()` | `build/src/core/theme.js` | **Gotcha: never flip theme by directly setting `html.setAttribute('data-theme', ...)`.** CSS still applies (native `[data-theme]` selectors don't care how the attribute changed), but the `wui:themechange` event — the *only* signal charts/gauges/maps listen for to know to redraw their canvas — never fires. Canvas content goes stale until some unrelated resize happens to redraw with fresh tokens as a side effect. Always call `WUI.toggleTheme()`/`WUI.setTheme()`, or use the declarative `[data-wui-theme-toggle]` attribute on any button (auto-wired, zero custom JS — see [conventions.md](conventions.md)). |
| `WUI.debounce(fn, wait)` / `WUI.throttle(fn, wait)` | `build/src/core/utils.js` | Timer-based (`setTimeout`), not rAF-based. |
| `WUIAnim.ringEntrance(el)` / `.sectionEntrance(containerEl)` | `JS/weoc-anim.js` | Animates `.wui-progress-ring-fill`'s `stroke-dashoffset` from a `data-target-pct` attribute (or the pre-rendered inline offset as a fallback). Reads nothing about the ring's rendered pixel size — geometry math is entirely `viewBox`-relative, so it's unaffected by the ring's fluid CSS sizing. |
