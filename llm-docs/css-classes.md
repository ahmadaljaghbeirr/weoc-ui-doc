# CSS Class-Family Index

[← Index](README.md) · Full worked examples: [`/docs/docs/kpi-recipes.html`](../docs/docs/kpi-recipes.html)

| Prefix | File | Notes |
|---|---|---|
| `.wui-w-{1-12}x{1-12}` | `weoc-grid.css` | Full 144-class bento tile-size matrix. **Verify the current ceiling before quoting a number** — `grep -oE '\.wui-w-[0-9]+x[0-9]+' CSS/weoc-ui/weoc-grid.css \| sort -u \| tail -5` — this has drifted from docs before. |
| `.wui-overflow-hidden` / `-auto` / `-y-auto` | `weoc-grid.css` | All `!important`. |
| `.wui-bento.is-page` | `weoc-grid.css` | Fixed-height, **non-scrolling** dashboard mode — `overflow:hidden` on every tile, needs an explicit page-height chain from an ancestor (`body{height:100vh}` → `.wui-main-div{height:100vh}` → `.wui-fill-area{flex:1 1 auto}` is the real chain the shared reset/layout CSS already provides for free). **Gotcha: using `is-page` in a plain page with no defined height silently hard-clips tile content** — no scrollbar, content just vanishes, zero console error. For a scrollable/flow-sized page instead, use `.wui-bento.cell-sm`/`cell-md`/`cell-lg` (`minmax(Npx, auto)` row sizing, respects `overflow:auto`). |
| `.wui-progress-ring` | `weoc-progress.css` | Fluid by default (`clamp()`); `.xs`/`sm`/`md`/`lg`/`xl` still work as fixed-size pins (win via normal CSS specificity). SVG geometry (`viewBox`, `r=52`, circumference `326.73`) is fully decoupled from wrapper CSS size — `weoc-anim.js`'s dash-offset math never needs the rendered pixel size. |
| `.wui-skeleton` | `weoc-feedback.css` | Width via `style="--wui-skeleton-w: 120px"` (custom-property override — sanctioned), **not** a literal `style="width:120px"` (that's the banned inline-style pattern — see [conventions.md](conventions.md)). |
| `.wui-tile` / `-hdr` / `-body` / `-footer` / `-legend` / `-icon` | `weoc-containers.css` | Structured dashboard-tile component. Base variant matches the real eoc-makeover dashboard-widget convention: uniform `padding:var(--space-2)` on `.wui-tile` itself (not per-region), hdr/footer **borderless by default** (`.has-border` is the additive opt-in — see next row). `.wui-tile-icon` = trailing icon chip in the header (`.blue`/`.orange`, matches the real board's `.widget-icon`). `.wui-tile-legend` = the anatomical slot for chart legends — pins to the bottom of `.wui-tile-body` via `margin-top:auto` (same mechanism `.wui-tile-footer` uses one level out), sits above the footer if one exists. A legend is content describing the chart, not a footer action — that's the rule. `.is-scrollable` on `.wui-tile` scrolls the body; without it, overflow clips (`.wui-tile{overflow:hidden}`) by design. Body-only mode = omit the hdr/footer divs. **Distinct from `.wui-bento-tile`** (the grid's transparent placement wrapper, `weoc-grid.css`) — drop `.wui-tile` *inside* a `.wui-bento-tile`. Also distinct from the *container-query name* `wui-tile` (`.wui-bento.is-page > * { container-name: wui-tile }`) — same string, unrelated concept, different CSS namespace. |
| `.has-border` vs `.flush` | `weoc-containers.css` | Two border-toggle modifiers, opposite polarity by design — pick based on the component's actual default, don't assume. `.wui-tile-hdr`/`-footer` and `.wui-card-hdr` default **borderless**; `.has-border` adds a divider. `.wui-panel-hdr`/`-footer`, `.wui-collapse-panel`, and `.wui-card-footer` default **bordered**; `.flush` removes it. |
| `[data-wui-display="tv"]` | `weoc-display-tv.css` | Opt-in TV/projector legibility-scale mode. **Not** in the `weoc-ui-core.css` barrel — a board adds this file's `<link>` only on the specific view(s) that need it (same opt-in posture as the old board-local `projector.css`, which was per-board only, never global, and no longer exists — this file recreates the concept at the library level; its exact scale multipliers are a first-pass judgment call pending real-TV visual QA). |
| `.wui-bar-row` | `weoc-progress.css` | Fixed `height` + `flex-shrink:0` (added — was missing this originally, which let it silently squish instead of scrolling inside a shrinking flex-column parent). Renders via `WUI.barRow()`, see [js-api.md](js-api.md). |
| `.wui-btn.neon-outline` / `.wui-fab.neon-outline` | `weoc-interactive.css` | The **original** neon-glow convention (pre-dates the 2026-07-27 rollout below) — every other `.neon`/`opts.neon` variant copies this one's token usage and visual weight. Per-severity (primary/secondary/success/warning/danger/info) `box-shadow: 0 0 2px var(--color-{X}-glow)` idle, `text-shadow: 0 0 4px var(--color-{X}-glow)` on hover. `--color-{X}-glow` tokens live in `agency-theme.css`, defined for all 6 severities across every theme variant file. |
| `.wui-badge.neon` / `.wui-chip.neon` | `weoc-labels.css` (2026-07-27) | Combine with an existing severity class (`.wui-badge.primary.neon`, etc.) — 6 rules each, `box-shadow` idle + extra hover glow layer + `text-shadow`, mirroring the button convention above. Docs: `interactive.html` ("Neon — outer glow, per color" under both Badge and Chip). |
| `.wui-plane.neon` | `weoc-containers.css` (2026-07-27) | Combine with an existing `.wui-plane` color/severity variant. Scaled up from the button glow's tight `0 0 2px` to `0 0 0.9rem -0.15rem` (roughly `--shadow-lg` magnitude) since a plane is a full card-sized surface, not a small chip — border-color also upgrades to match. Idle-only, no hover state (static container, not interactive). Docs: `containers.html`. |
| `.wui-progress-ring.neon` / `.wui-progress-bar.neon` | `weoc-progress.css` (2026-07-27) | Combine with an existing severity variant; targets the `-fill` element (`.wui-progress-ring.neon.primary .wui-progress-ring-fill`, etc.), 6 rules each. **Uses `filter: drop-shadow(...)`, not `box-shadow`** — these are SVG strokes / rounded-corner bar fills, and drop-shadow follows the actual rendered shape where box-shadow would just draw a rectangle around the bounding box. `.wui-progress-ring-segment.neon` (multi-segment ring) also covered. Docs: `progress.html`. |
| `.wui-chart-neon-{severity}` / `.wui-barrow-neon-{severity}` | `weoc-charts.css` (**new file**, 2026-07-27, imported by `weoc-ui-core.css` as module #21) | Toggled programmatically by `opts.neon` on `WUI.chart()`/`WUI.barRow()` — not meant to be hand-applied in markup (compare to every other `.neon` row above, which IS a markup class). `filter: drop-shadow(...)` targeting `.u-wrap > canvas` (uPlot's actual data canvas — verified against `uPlot.iife.min.js`'s DOM construction, deliberately avoids the axis/legend/cursor layers) and `.wui-bar-row .fill` respectively. `WUI.pie`/`donut`/`gauge`'s `opts.neon` does NOT use this file or a class at all — those glow via direct canvas `ctx.shadowBlur`/`shadowColor` instead, since they draw straight to Canvas 2D. Full picture in [js-api.md](js-api.md)'s `opts.neon` row. |
