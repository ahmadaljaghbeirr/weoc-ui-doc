Tables
Three table variants for WebEOC record views: a flat bordered grid, a spacious card-row layout, and a dense operator log with expandable detail rows.
info
Add-on module — load weoc-tables.css after the core barrel
Tables are not in weoc-ui-core.css. Add <link rel="stylesheet" href="weoc-tables.css"> on table views.

Row color accents

Left-border accent: add one color class to any <tr>. Works on all three table variants — standard and cards get a 3px border; on wui-table-log it drives --_tier so the 4px border and elapsed time color both update.

Row class Use case
is-primary Active / selected focus
is-success Resolved / closed / confirmed
is-info Informational / monitoring
is-warning Caution / needs attention
is-danger Danger / escalated / critical
is-secondary Muted / archived / low priority
Row fill states

Background-fill variants for semantic status rows. is-highlighted = warning fill · is-error = danger fill · is-selected = primary fill.

Other row states

is-disabled, is-loading, is-dragging, is-dragover.

Column widths (on <th>)

wui-col-sm (80px) · wui-col-index (150px) · wui-col-md (180px) · wui-col-primary (40%) · wui-col-secondary (25%) · wui-col-actions (80px, centered). Sort indicators: is-sortable, is-sort-asc, is-sort-desc.

receipt_longwui-table-log

Dense operator log. Each record is a pair of rows: a wui-log-row and a following wui-log-detail-row. The color accent (is-primary / is-success / is-info / is-warning / is-danger / is-secondary) goes on the data row only — the detail row inherits via the adjacent sibling rule. The detail row reveals when the data row has is-open (toggled by JS via data-wui-row="true"). Zebra striping is automatic. Tier-color overrides belong in the consuming view's own CSS.

warning
data-wui-row="true" — value form required in WebEOC XML
The expand/collapse wiring reads data-wui-row. WebEOC's XML parser rejects bare boolean attributes, so always write ="true".
