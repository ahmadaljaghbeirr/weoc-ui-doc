Forms
Input-view building blocks: grouped fieldsets with field rows, labelled controls, and a sticky form footer for meta and actions.
info

tunewui-fieldset

A titled section grouping field rows. wui-fieldset-legend (optional icon) → wui-fieldset-sub → wui-fieldset-body holding field-row groups. Each field-row is a 2-column grid by default; full = 1 col, three / four = 3 / 4 cols. Add plain to the fieldset to drop the surface chrome.

lockReadonly fields

Use [readonly] (native HTML) or the .is-readonly class for controls that display existing data and must not be edited. The dashed border signals non-interactive; the muted surface and text keep the content readable without the weight of a disabled field.

<!-- Native readonly attribute (preferred for real inputs) -->
<div class="field-item is-readonly">
  <label class="field-label">Created by</label>
  <input type="text" class="form-control" readonly value="J. Rivera (WebEOC)">
</div>

<!-- Class-only version (use when [readonly] is not available, e.g. TomSelect output) -->
<div class="field-item is-readonly">
  <label class="field-label">Status</label>
  <input type="text" class="form-control is-readonly" value="Monitoring">
</div>

<!-- Readonly textarea -->
<div class="field-item is-readonly">
  <label class="field-label">Prior assessment</label>
  <textarea class="form-control" readonly>Existing content…</textarea>
</div>
info
Two selectors, same styles
[readonly] covers native inputs and textareas. .is-readonly covers everything else — custom controls, TomSelect wrappers, display-only divs — so you can use the same visual language across all field types.
visibility
Readonly ≠ disabled
Readonly fields are still focusable and the text is copyable. If the control should be completely inert (no tab stop, grayed out), use the disabled attribute or .is-disabled instead.

arrow_drop_down_circleTomSelect

Powered by tom-select-factory.js. Add class="tomselect" to any <select> and call TomSelectFactory.init(). The factory injects a blank placeholder option, auto-resyncs dependent cascades via MutationObserver, and handles edit-mode repopulation for multi-selects.

info
Load order
tom-select.min.css → tom-select-agency.css in <head>, then TomSelect JS → tom-select-factory.js. Call TomSelectFactory.init() after the DOM is ready.
Single select

One item, dropdown search built in. data-allow-empty="true" keeps the blank option in the dropdown so the user can actively re-clear a field — omit for required fields (placeholder shows on load, but can't be re-selected once a value is chosen).

<select class="tomselect" data-placeholder="Select priority…">
  <option value="low">Low</option>
  <option value="high">High</option>
</select>

<!-- Clearable: user can re-select blank from the dropdown -->
<select class="tomselect" data-allow-empty="true" data-placeholder="Optional…">…</select>

<script>TomSelectFactory.init();</script>
Multi-select

Add multiple (or data-multi="true"). Selections render as removable chips; an inline search field is always visible in the dropdown. In edit mode, restore comma-separated values with repopulateMultiSelect('FieldName', xslValue) — WebEOC doesn't restore multi-select natively.

<select class="tomselect" multiple data-placeholder="Select agencies…">
  <option value="fire">Fire Department</option>
  <option value="ems">EMS</option>
  …
</select>
Creatable

data-create="true" — type a new value and press Enter or Tab to add it. createOnBlur is also enabled so tabbing away commits the typed entry automatically.

<select class="tomselect" multiple data-create="true" data-placeholder="Type to add…">
  <option value="urgent">Urgent</option>
  …
</select>
Dependent selects (parent / child)

In WebEOC the board engine replaces the child's <option> list when the parent changes — the factory's MutationObserver detects the option-count change and resyncs. For non-WebEOC contexts, wire data-on-change on the parent to a function that rebuilds child options and calls TomSelectFactory.get('child')?.clearOptions().sync(). The demo below uses this pattern.

<!-- Parent: fires data-on-change with the selected value -->
<select name="Category" class="tomselect" data-on-change="onCategoryChange">…</select>

<!-- Child: data-parent triggers auto-resync when parent changes (WebEOC) -->
<select name="SubCategory" class="tomselect" data-parent="Category">…</select>
Custom option renderer

Register a template with TomSelectFactory.registerTemplate(name, def) before calling init(), then point the select at it with data-render="name". TomSelect copies all data-* attributes from <option> elements into the option data object.

<select class="tomselect" data-render="PersonTemplate">
  <option value="jr" data-role="Incident Commander" data-dept="EOC">J. Rivera</option>
  …
</select>

TomSelectFactory.registerTemplate('PersonTemplate', {
  option: function(data) {
    return '<div class="ts-person-option">' +
      '<div class="ts-person-name">' + data.text + '</div>' +
      '<div class="ts-person-meta">' + data.role + ' · ' + data.dept + '</div>' +
    '</div>';
  },
  item: function(data) { return '<div>' + data.text + '</div>'; }
});
TomSelectFactory.init();
States — disabled & readonly

Disabled (disabled attr or TomSelectFactory.disable('key')) renders with reduced opacity — fully inert, no tab stop. Readonly (.is-readonly on the .ts-wrapper after init) matches the form-control readonly style: dashed border, muted surface, text copyable, no dropdown.

Fully inert — grayed out, no tab stop.
Focusable, text copyable — no dropdown opens.
<!-- Disabled -->
<select class="tomselect" disabled>…</select>
TomSelectFactory.disable('key'); // programmatic

<!-- Readonly: add .is-readonly to the .ts-wrapper after init -->
TomSelectFactory.get('key').wrapper.classList.add('is-readonly');

<!-- Wrap in .field-item.is-readonly to dim the label too -->
<div class="field-item is-readonly">
  <label class="field-label">Label</label>
  <select class="tomselect">…</select>
</div>
calendar_todayFlatpickr

Powered by flatpickr-factory.js. Add data-fp-preset to any <input> — the factory auto-inits on DOMContentLoaded and dispatches a bubbling fp:change CustomEvent on every date change. Re-init late-injected inputs with FlatpickrFactory.init(scope).

info
Load order
flatpickr.min.css → flatpickr-agency.css in <head>, then flatpickr.min.js → flatpickr-factory.js. Already-initialized inputs are skipped on re-call.
Date pickers
<input class="flatpickr-input flat-date" data-fp-preset="date">      <!-- YYYY-MM-DD -->
<input class="flatpickr-input flat-date" data-fp-preset="date-dmy">  <!-- DD/MM/YYYY -->
Time pickers
<input class="flatpickr-input flat-time" data-fp-preset="time">    <!-- 24hr -->
<input class="flatpickr-input flat-time" data-fp-preset="time-12"> <!-- 12hr -->
Date + time
<input data-fp-preset="datetime">          <!-- YYYY-MM-DD HH:MM, 24hr -->
<input data-fp-preset="datetime-dmy">      <!-- DD/MM/YYYY HH:MM, 24hr -->
<input data-fp-preset="datetime-12">       <!-- DD/MM/YYYY h:MM AM/PM -->
<input data-fp-preset="datetime-seconds">  <!-- YYYY-MM-DD HH:MM:SS -->
Constrained — future & past only

The min/max is refreshed on each open so "today" is always the actual current day at the moment the picker opens, not when the page loaded.

<input data-fp-preset="future-date">      <!-- no past dates; min refreshed on open -->
<input data-fp-preset="past-date">        <!-- no future dates -->
<input data-fp-preset="future-datetime">  <!-- date + 24hr time, future only -->
<input data-fp-preset="past-datetime">    <!-- date + 12hr time + seconds, past only -->
Range pair (start / end)

Both inputs share a data-fp-range-group. The start's selection becomes the end's minimum and vice versa — they constrain each other automatically on close.

arrow_forward 
<input data-fp-preset="range-start"
       data-fp-range-group="incident-window"
       data-fp-range-role="start">
<input data-fp-preset="range-end"
       data-fp-range-group="incident-window"
       data-fp-range-role="end">
Inline (embedded) calendar

data-fp-inline="true" renders the calendar permanently in place — no popup. Works with any preset. Useful for date panels and filter widgets in dashboards.

<input data-fp-preset="date" data-fp-inline="true">
<input data-fp-preset="datetime" data-fp-inline="true">
Readonly

Flatpickr always sets [readonly] on its input internally. For a true display-only field, add .is-readonly to the input and call fp.set('clickOpens', false) on the instance. The dashed border and muted surface match the form-control readonly language.

<!-- Static readonly (no factory init on this input) -->
<div class="field-item is-readonly">
  <label class="field-label">Date</label>
  <input class="flatpickr-input flat-date is-readonly" readonly value="2026-06-24">
</div>

<!-- Block picker on a live instance -->
var fp = document.querySelector('#myDate')._flatpickr;
if (fp) { fp.set('clickOpens', false); }
document.querySelector('#myDate').classList.add('is-readonly');
